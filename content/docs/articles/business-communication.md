# 비즈니스 커뮤니케이션의 표현

업무 메일과 회의록에서 반복해서 보이는, 완곡하지만 분명한 문장들.

> [!NOTE]
> 이 페이지는 템플릿을 보여 주기 위해 직접 쓴 **예시 문장**이다.

{{< sentence
  en="I want to make sure we are aligned before we commit to a date."
  ko="날짜를 확정하기 전에 우리 인식이 맞는지 확인하고 싶다."
  note="`be aligned`는 **같은 이해에 도달해 있다**는 뜻으로, `agree`보다 부드럽고 조직 안에서 훨씬 자주 쓰인다. `commit to a date`는 '날짜를 못 박다'라는 의미의 고정 표현. `I want to make sure ~`로 시작하면 이견을 제기하는 문장인데도 공격적으로 들리지 않는다."
  app1="Before I send this out, I want to make sure we are aligned on the scope."
  app1ko="이걸 보내기 전에 범위에 대해 우리 인식이 맞는지 확인하고 싶다."
  app2="We are not aligned on what 'done' means for this milestone."
  app2ko="이 마일스톤에서 '완료'가 무엇인지에 대해 우리 인식이 맞지 않는다."
>}}

{{< sentence
  en="That is doable, but it would push the launch out by about two weeks."
  ko="가능하긴 한데, 그러면 출시가 2주 정도 밀린다."
  note="요청을 거절하지 않으면서 **비용을 즉시 붙이는** 전형적인 화법이다. `doable`은 '할 수는 있다'는 뉘앙스의 구어체이고, `push ~ out`은 일정을 뒤로 미룬다는 뜻의 구동사다. `about`을 넣어 추정임을 밝히는 것도 그대로 가져다 쓸 만하다."
  app1="Adding SSO is doable, but it would push the beta out by a sprint."
  app1ko="SSO 추가는 가능하지만, 그러면 베타가 스프린트 하나만큼 밀린다."
  app2="Supporting both formats is doable; it just moves the testing effort onto QA."
  app2ko="두 포맷을 모두 지원하는 건 가능하다. 다만 테스트 부담이 QA로 넘어갈 뿐이다."
>}}

{{< sentence
  en="To close the loop on last week's discussion, we decided to keep the current provider."
  ko="지난주 논의를 마무리 짓자면, 현재 공급사를 유지하기로 했다."
  note="`close the loop`는 **열려 있던 논의를 매듭짓고 결과를 공유하다**라는 관용구다. 메일 첫 문장으로 쓰면 '이건 후속 보고'라는 신호가 되어 독자가 맥락을 바로 잡는다. `To close the loop on X, we ...` 형태로 통째로 외워 두면 좋다."
  app1="To close the loop on the incident, the root cause was an expired certificate."
  app1ko="장애 건을 마무리 짓자면, 근본 원인은 만료된 인증서였다."
  app2="Just closing the loop here: the client approved the revised timeline this morning."
  app2ko="이 건 마무리 공유합니다 — 고객사가 오늘 아침 수정된 일정을 승인했습니다."
>}}

{{< sentence
  en="I may be missing context here, but the numbers in slide 4 do not match the dashboard."
  ko="제가 맥락을 놓쳤을 수도 있는데, 4번 슬라이드 숫자가 대시보드와 맞지 않습니다."
  note="`I may be missing context` 는 **지적하기 전에 자신의 무지 가능성을 먼저 인정하는** 장치다. 오류를 지적하면서도 상대를 몰아세우지 않게 해 준다. 뒤에는 감정 없이 사실만 놓는 게 이 화법의 핵심 — `do not match`처럼 관찰 가능한 서술로 끝낸다."
  app1="I may be missing context, but this endpoint seems to be called twice per render."
  app1ko="제가 맥락을 놓쳤을 수도 있는데, 이 엔드포인트가 렌더링마다 두 번 호출되는 것 같습니다."
  app2="I might be missing something, but the migration script does not seem to handle nulls."
  app2ko="제가 뭔가 놓쳤을 수도 있지만, 마이그레이션 스크립트가 null을 처리하지 않는 것 같습니다."
>}}

{{< sentence
  en="Let's park this and come back to it once we have the usage data."
  ko="이 건은 일단 접어 두고, 사용량 데이터가 나오면 다시 보자."
  note="`park`는 회의에서 **결론을 미루되 버리지는 않는다**는 뜻으로 쓰는 동사다. 그냥 `let's skip this`라고 하면 '무시하자'로 들리지만, `park`는 '주차해 두었다가 꺼낸다'는 이미지라 참석자를 존중하는 느낌이 남는다. 재개 조건(`once we have ~`)을 붙이는 게 세트다."
  app1="Let's park the pricing question and come back to it after the pilot."
  app1ko="가격 문제는 일단 접어 두고 파일럿 끝나고 다시 보자."
  app2="We parked the rewrite last quarter; it is worth reopening now that the team has grown."
  app2ko="지난 분기에 재작성 건을 보류해 뒀는데, 팀이 커졌으니 다시 꺼내 볼 만하다."
>}}
